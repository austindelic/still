title: Getting Started
description: Build Still locally and try the first project workflow.
---

Still is easiest to understand from a small project. This page uses the
repository build because the CLI is under active development.

## Build The CLI

From the CLI workspace:

```bash
cd apps/cli
cargo build -p still
```

Run help through the local binary:

```bash
cargo run -p still --bin still -- --help
```

## Create A Project File

Start a project config:

```bash
still init
```

That creates `still.toml` and trusts the generated file. When you edit the file
later, review it and run `still trust` before executing project-defined tasks,
services, env files, or external agent behavior.

## Install A Tool

Install requests are typed by item kind and may include an explicit source:

```bash
still install --tool cargo:ripgrep@14.1.1
still install --tool --cargo ripgrep@14.1.1 cargo-nextest
```

If no version is provided, Still treats it as `latest`. If no source is
provided, Still uses source auto-selection for the item kind and current
platform.

## Try A Small Config

```toml
[tools]
node = "22"
python = "3.12"

[packages]
latest = ["ripgrep", "fd", "jq"]

[env]
NODE_ENV = "development"
files = [".env", ".env.local"]

[tasks.lint]
run = [
  "cargo fmt --check",
  "cargo clippy --all-targets --all-features",
]
```

Then reconcile and run inside the managed environment:

```bash
still sync
still run cargo test
still task lint
```

## Open The TUI

The default build prints help when run with no command. Build with the `tui`
feature to include the terminal UI; in that build, running `still` with no
command opens the TUI.

```bash
cargo run -p still --features tui --bin still
```
