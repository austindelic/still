---
title: Tasks And Services
description: Project tasks, long-running services, and their config shape.
---

Tasks and services keep project commands next to the tools and packages they
need. They are trust-sensitive because they execute project-defined behavior.

## Tasks

Tasks are named commands or task graphs.

```toml
[tasks]
test = "cargo test"
fmt = "cargo fmt"
dev = "cargo run"

[tasks.lint]
description = "Run lint checks"
run = [
  "cargo fmt --check",
  "cargo clippy --all-targets --all-features",
]

[tasks.ci]
description = "Run full CI"
depends = ["lint", "test"]
run = "echo CI passed"
```

Short form works for simple commands. Expanded form adds descriptions,
dependencies, service requirements, and multi-step runs.

Run a task:

```bash
still task lint
```

List configured tasks:

```bash
still task
```

## Services

Services are commands that should be available while the project is active:
databases, Docker, local daemons, or a dev server.

```toml
[services]
docker-compose = "docker compose up"
dev-server = { task = "dev-server" }

[services.docker]
start = { task = "docker:start" }
stop = { task = "docker:stop" }
check = { task = "docker:check" }
```

Services can point at tasks so startup, shutdown, and health checks stay in one
file.

```bash
still services status
still services start docker
still services check docker
```

`sync` prepares tools, packages, apps, agents, and lockfile state. It does not
start services automatically in the v0.1 contract.
