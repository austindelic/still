Agents are desired state like tools and packages. Still can materialize shared instructions and managed skills so every developer gets the same project-aware assistant setup.

## Basic Setup

```toml
[agents]
targets = ["claude", "codex"]
instructions = "AGENTS.md"
skills = ["rust-review", "repo-auditor"]
```

Supported initial targets are `claude` and `codex`.

## Skill Sources

For explicit external or pinned sources, use the table form.

```toml
[agents]
targets = ["claude", "codex"]
instructions = "AGENTS.md"

[agents.skills]
repo-auditor = "repo-auditor"
external-skill = { url = "https://example.com/skill", version = "1.2.0" }
pinned-skill = "https://example.com/skill:1.2.0"
latest-skill = "https://example.com/skill"
rust-review = { source = "rust-review", auto = true, tools = ["rust@stable@rustup"], packages = ["llvm"] }
```

Resolution rules:

- Bare names such as `rust-review` resolve as official Still skill names.
- `owner/name` resolves from a GitHub-owned skill source.
- URL strings resolve external skills.
- URL strings may include a version suffix as `<URL>:<VERSION>`.
- Inline entries can use `{ source = "..." }` for official or GitHub shorthand.
- Inline entries can use `{ url = "...", version = "..." }` for external sources.
- `skills` can be an array or an `[agents.skills]` table, but not both in the same TOML document.

## Managed Skill Files

Still-managed skills materialize under `.agents/skills/<skill-name>` in v0.1.

Still also manages `.agents/skills/.gitignore` with anchored entries for only the managed skill directories.

```text
# still-managed skills
/rust-review/
/repo-auditor/
```

Rules:

- Still must not add `*`, `/*`, or `.agents/skills/*` rules that hide all skills.
- User-authored custom skills remain commit-ready unless listed in the generated ignore file.
- Each Still-managed skill directory includes a marker such as `.still-managed`.
- Still refuses to overwrite an existing unmarked custom skill directory with the same name.
- Removing a skill from config removes it from the generated ignore file. Deleting the local directory is only allowed for marked managed folders.

## Auto Dependencies

Skill entries can declare tool, package, and app requirements.

```toml
[agents.skills]
rust-review = { source = "rust-review", auto = true, tools = ["rust@stable@rustup"], packages = ["llvm"] }
```

A materialized skill can also include `still.skill.toml`.

```toml
[dependencies]
tools = ["cargo-nextest@0.9.99@cargo"]
packages = ["llvm"]
apps = ["zed"]
```

Behavior:

- `auto = true` allows Still to accept declared requirements and add missing entries to config during sync.
- If `auto` is absent or false, Still reports missing skill dependencies but does not mutate config automatically.
- `agents check` reports pending auto dependencies without writing them.
- `agents sync` does not write auto dependencies unless `--accept-auto-deps` is present.
- Auto-added dependencies are normal desired state entries in `still.toml`; they are not specially annotated in v0.1.
- Removing a skill does not automatically remove tools, packages, or apps.

## Commands

```bash
still agents
still agents list
still agents check
still agents sync
still agents sync --accept-auto-deps
```

Agents and external skills are trust-sensitive because they can affect executable assistant behavior.
